# Package and workspace layout

## Repository packages

- `packages/core` is the public runtime and SDK (`@dyna/core`). It owns market, agent, risk, execution, governance, orchestration, and persistence implementation.
- `packages/cli` is the installable `dynatrader` command and daemon package. Its root exports preserve the previous SDK entry points by forwarding to `@dyna/core`.
- `packages/ui` is the installable terminal UI (`@dynatrader/ui`).
- `packages/dynamind-api-plugin` is the separately versioned and published API plugin. The CLI depends on it so configured bundled plugin resolution works in clean installs.
- The repository root is a private Bun workspace for scripts, docs, release orchestration, and cross-package checks. It is not a published runtime package.

Changesets versions and publishes each package independently. Package dependency ranges express the release order; the release workflow runs the release checks before publishing.

## User data paths

`~/.dynatrader` is the private state home. It contains `config.yaml`, `auth.json`, credentials, databases, audit records, logs, cron state, run cards, and other generated state.

`~/.dynatrader/workspace` is agent-owned content. It contains identity and policy files, agents, skills, commands, tools, adapters, personas, and user memory.

Set `DYNA_STATE_DIR` to relocate private state. Set `DYNA_WORKSPACE` to relocate agent-owned content. If only `DYNA_STATE_DIR` is set, the workspace defaults to its `workspace/` child. Legacy repository workspace material from the 2026-09-29 migration is preserved under `~/.dynatrader/imports/` and imported without overwriting existing files.

The tracked `templates/workspace` directory contains setup guidance only. It must not contain runtime code, build output, tests, credentials, databases, logs, or generated agent runs. Runtime workspace initialization is generated by `dynatrader init`.
